## Project Overview

This project explores pilot preferences for cockpit interface placement and design. It consists of three components:

1. **Survey website** — collects pilot preferences via a swipe-based layout survey
2. **Data visualiser** — analyses and visualises survey results
3. **Unity cockpit app** — a 3D cockpit design tool with AI feedback based on regulations and survey data

## Component 1 — Survey Website

### What it does
A web survey deployed on the LMU lab server that collects pilot preferences:
- **Phase 1:** GDPR consent + demographic questions
- **Phase 2:** Swipe deck — pilots mark each cockpit system as fixed or flexible in position
- **Phase 3:** Zone mapper — for flexible systems, pilots tap zones on a cockpit SVG and set preferred interface type (physical/touchscreen/mixed)
- **Phase 4:** Display preferences — for display systems, pilots answer questions about size, grouping, and redundancy

## Component 3 — AI Feedback Server

### What it does
A local Python server that:
1. Holds regulation documents in a vector database (ChromaDB)
2. Receives cockpit layout JSON from Unity
3. Retrieves relevant regulation chunks
4. Calls Claude API to generate structured feedback
5. Returns feedback to Unity for display in the assistant UI

### Setup (first time)
```bash
cd ai-server
python -m pip install anthropic chromadb pypdf2 flask flask-cors sentence-transformers
```

Create `.env` file:
```
ANTHROPIC_API_KEY=sk-ant-your-key-here
```
Get an API key from **console.anthropic.com** (requires account with billing credit — approximately $5 is sufficient for extensive testing).

Add regulation PDFs to `documents/`:
- CS-25 Book 1 Subpart F
- AMC 25.1302
- FAR Part 25 (equivalent sections)
- A320/B737 FCOM cockpit sections (optional)

Index documents (run once, or when documents change):
```bash
python ingest.py
```

Start server:
```bash
python server.py
```
Server runs on `http://localhost:5000`.

### API endpoints
- `GET /health` — server status and chunk count
- `POST /feedback` — send layout JSON, receive feedback array
- `POST /chat` — send a question about the layout, receive a text reply

### Updating the survey summary
Once sufficient survey responses are collected, update the `SURVEY_SUMMARY` string in `server.py` with actual aggregate statistics from the exported data. The current version uses a manually written placeholder summary.

## Component 4 — Unity Cockpit App

### What it does
A first-person 3D cockpit design tool intended for **cockpit designers, human factors engineers, and aviation UI specialists** — not pilots. Users design a cockpit layout by placing systems onto panels, with optional real-time AI guidance based on airworthiness regulations and aggregated pilot survey data.

The intended research workflow is:
1. **Designers** use the app to create cockpit layouts — some with the AI assistant enabled, some without
2. **Pilots** then evaluate those layouts (separately), providing feedback on whether placements match their expectations and preferences
3. **Researchers** compare layouts made with vs. without AI assistance to assess whether the assistant produces better outcomes — i.e. layouts that pilots rate more favourably

The AI assistant draws on two sources of ground truth: aviation regulations (CS-25, FAR Part 25, AMC 25.1302) and the aggregated results of the pilot preference survey (Component 1).

### Requirements
- Unity 6 (tested on 6000.0.f1)
- ProBuilder package (install via Package Manager)
- Universal Render Pipeline

### Opening the project
Open `CockpitDSG/` as a Unity project. The main scene is in `Assets/Scenes/`.

### Key scripts (Assets/Scripts/)
| Script | Purpose |
|---|---|
| `PlayerController.cs` | First-person movement and mouse look |
| `PanelGrid.cs` | Grid system on each cockpit panel |
| `SystemData.cs` | ScriptableObject defining each cockpit system |
| `SystemTile.cs` | Placed tile on a panel |
| `PlacementController.cs` | System selection, ghost preview, placement logic |
| `SystemMenu.cs` | Tab menu UI for selecting systems |
| `LayoutSerializer.cs` | Converts current layout to JSON |
| `AIClient.cs` | HTTP client sending layout to Python server |
| `AssistantUI.cs` | In-game feedback bubble and chat panel |

### System data assets
Located in `Assets/Resources/Systems/` — one ScriptableObject per cockpit system (73 total). Each defines the system ID, display name, grid size, whether it's resizable, and tile color.

### Running with AI feedback
1. Start the Python server: `python server.py` in `ai-server/`
2. Press Play in Unity
3. Place systems on panels — feedback appears automatically after 2 seconds
4. Press F1 to open the assistant chat panel
5. Press Escape to close

### Controls
| Key | Action |
|---|---|
| WASD | Move |
| Mouse | Look around |
| Tab | Open system menu |
| Left click | Place system / select tile |
| Right click | Cancel placement |
| Shift+Scroll | Resize height (resizable systems) |
| Ctrl+Scroll | Resize width (resizable systems) |
| F1 | Open/close AI assistant |
| Escape | Close menus / chat |
